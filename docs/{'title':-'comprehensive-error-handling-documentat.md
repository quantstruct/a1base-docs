### Error Response Examples

Here are some examples of error responses in JSON format:

#### 400 Bad Request

This error indicates that the request was malformed or missing required parameters.

```json
{
  "detail": [
    {
      "loc": [
        "body",
        "to"
      ],
      "msg": "field required",
      "type": "value_error.missing"
    }
  ]
}
```

**Cause:** The `to` field was missing in the request body.

**Solution:** Ensure that all required parameters are included in the request and that they are in the correct format.

#### 422 Unprocessable Entity

This error indicates that the request was well-formed, but the server was unable to process the instructions contained within. This is often due to validation errors.

```json
{
  "detail": [
    {
      "loc": [
        "body",
        "from"
      ],
      "msg": "value is not a valid phone number",
      "type": "value_error"
    }
  ]
}
```

**Cause:** The `from` field contained an invalid phone number.

**Solution:** Ensure that the data you are sending conforms to the expected format and validation rules.  In this case, verify that the `from` field contains a valid phone number.

#### 500 Internal Server Error

This error indicates that something went wrong on the server.

```json
{
  "detail": "An unexpected error occurred."
}
```

**Cause:** A generic server-side error.

**Solution:**  If you encounter this error, please try again later. If the error persists, contact support and provide the request details and the error message.

### Authentication Errors

Authentication errors typically return a 401 Unauthorized or 403 Forbidden status code.

#### 401 Unauthorized

This error indicates that the request requires authentication.

**Cause:** Missing or invalid API key or secret.

**Solution:** Ensure that the `x-api-key` and `x-api-secret` headers are included in the request and that they are valid.

#### 403 Forbidden

This error indicates that the server understands the request but refuses to authorize it.

**Cause:** Insufficient permissions for the requested resource.

**Solution:** Verify that the account associated with the API key has the necessary permissions to access the requested resource.

### Best Practices for Error Handling

*   **Implement robust error handling in your application:**  Don't just check for success; handle potential errors gracefully.
*   **Log error responses:**  Logging error responses can help you diagnose and resolve issues more quickly.
*   **Provide informative error messages to the user:**  If possible, provide user-friendly error messages that explain what went wrong and how to fix it.
*   **Retry failed requests:**  For transient errors (e.g., network issues), consider retrying the request after a short delay.
