
# Email Functionality Documentation

## Email Overview

This document provides comprehensive information for developers and email integration specialists on how to utilize the email functionality within our platform. It covers various aspects, including authentication, creating, sending, and receiving emails, as well as webhook integration. This documentation complements the OpenAPI specification and provides practical examples to facilitate seamless integration.

## Authentication

All email-related endpoints require authentication.  You can authenticate using API keys or OAuth 2.0.  Refer to the [Authentication Documentation](link-to-authentication-docs) for detailed instructions on obtaining and using your credentials.

**Example (API Key in Header):**

```
Authorization: Bearer YOUR_API_KEY
```

## Creating Emails

The `/v1/emails/{accountId}/create-email` endpoint allows you to create email drafts.  These drafts can then be sent using the sending endpoint.

**Request:**

```
POST /v1/emails/{accountId}/create-email
Content-Type: application/json
Authorization: Bearer YOUR_API_KEY

{
  "subject": "Hello from our platform!",
  "body": "This is a test email.",
  "recipient": "test@example.com",
  "sender": "noreply@yourplatform.com",
  "cc": "cc@example.com",
  "bcc": "bcc@example.com"
}
```

**Parameters:**

| Parameter   | Type   | Description                               | Required |
|-------------|--------|-------------------------------------------|----------|
| accountId   | string | The ID of the account.                    | Yes      |
| subject     | string | The subject of the email.                 | Yes      |
| body        | string | The body of the email.                    | Yes      |
| recipient  | string | The recipient's email address.            | Yes      |
| sender      | string | The sender's email address.               | Yes      |
| cc          | string | The CC email address (optional).          | No       |
| bcc         | string | The BCC email address (optional).         | No       |

**Response:**

```json
{
  "emailId": "unique-email-id",
  "status": "draft",
  "message": "Email draft created successfully."
}
```

## Sending Emails

The `/v1/emails/{accountId}/send` endpoint is used to send email drafts that have been created.

**Request:**

```
POST /v1/emails/{accountId}/send
Content-Type: application/json
Authorization: Bearer YOUR_API_KEY

{
  "emailId": "unique-email-id"
}
```

**Parameters:**

| Parameter   | Type   | Description                               | Required |
|-------------|--------|-------------------------------------------|----------|
| accountId   | string | The ID of the account.                    | Yes      |
| emailId     | string | The ID of the email draft to send.        | Yes      |

**Response:**

```json
{
  "status": "sent",
  "message": "Email sent successfully."
}
```

**Example Types:**

*   **Simple Text Email:**  The example above demonstrates sending a simple text email.

*   **Emails with Attachments:**  To send emails with attachments, you'll need to encode the attachment and include it in the request.  The following example shows how to include a single attachment.

    **Request (with attachment):**

    ```
    POST /v1/emails/{accountId}/create-email
    Content-Type: application/json
    Authorization: Bearer YOUR_API_KEY

    {
      "subject": "Email with Attachment",
      "body": "This email has an attachment.",
      "recipient": "test@example.com",
      "sender": "noreply@yourplatform.com",
      "attachments": [
        {
          "filename": "document.pdf",
          "content": "BASE64_ENCODED_PDF_CONTENT",
          "contentType": "application/pdf"
        }
      ]
    }
    ```

    **Attachment Parameters:**

    | Parameter   | Type   | Description                               | Required |
    |-------------|--------|-------------------------------------------|----------|
    | filename    | string | The name of the attachment file.          | Yes      |
    | content     | string | The Base64 encoded content of the file. | Yes      |
    | contentType | string | The MIME type of the file.                | Yes      |

## Receiving Emails

The `/v1/emails/mailserver/incoming` endpoint is used to receive incoming emails.  This endpoint is typically configured as a webhook target for your mail server.

**Note:** This endpoint requires specific configuration on your mail server to forward incoming emails to it.  Consult your mail server documentation for instructions on setting up email forwarding or webhooks.

## Webhook Integration

Our platform can send webhooks to your application when new emails are received.  You can configure the webhook URL in your account settings.

**Webhook Payload Example:**

```json
{
  "type": "email.received",
  "data": {
    "emailId": "unique-email-id",
    "sender": "sender@example.com",
    "recipient": "your-webhook@example.com",
    "subject": "Incoming Email",
    "body": "The body of the incoming email.",
    "receivedAt": "2024-01-01T12:00:00Z",
    "attachments": [
      {
        "filename": "report.csv",
        "contentType": "text/csv",
        "size": 1024
      }
    ]
  }
}
```
